# 个人资料库填写说明

此目录是个人简历 AI 的唯一资料来源。博客文章、关于页面、项目页均不会自动导入。

1. 编辑模板，将注释替换为真实正文。可以复制项目文档，每份资料必须使用唯一的英文小写 `id`（允许数字和连字符）。
2. `type` 使用 resume、project 或 contact；`skills` 填技能关键词数组，用于检索；`links` 填 `label` 与 `url` 对象数组，仅支持 HTTPS 公开链接。
3. 核实内容允许公开后，将 `status: draft` 改为 `status: published`。没有正文或只有注释的模板不会被索引。不要把待填写提示、示例经历当成真实资料发布。
4. 简历集中维护个人简介、求职方向、教育、工作经历与技能，项目细节和成果保留在各项目文档中。简历会优先进入每次回答上下文，建议保持精简（目前每份资料最多读取两个片段）。
5. 项目必须区分本人职责与团队成果。量化成果写清基线、时间、计算口径和证据；未知数据不填写猜测值。
6. 联系方式在 contact.md 的 `contact` 字段填写 HTTPS 联系页面或 `mailto:公开邮箱`，同时填写正文联系说明并发布。仅保留一份公开联系资料；填写后访客发送问题即可看到联系入口。
7. 运行 `pnpm build` 或 `node scripts/build-knowledge.mjs` 重建索引，部署后生效。本地聊天开发时也需要先重建。

所有已发布内容可能展示给任何访客并发送给模型服务。不要提交私密资料；draft 只是索引开关，不是 Git 仓库的访问权限保护。

AI 按已发布简历介绍求职方向与实际经历，不会把求职方向作为实际经验。未发布任何资料时只显示资料待补充提示。
